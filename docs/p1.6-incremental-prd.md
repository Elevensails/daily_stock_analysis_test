## 1. 产品目标

> **让筹码分布与 RAG 新闻在 GitHub Actions CI 环境中也能稳定产出真实数据，消除报告中的"未启用 / 未检索到"空洞段落。**

拆解为三条正交子目标：

| # | 子目标 | 衡量口径 |
|---|---|---|
| G1 | A 股个股报告的筹码分布段落有真实数据 | CI 产出的 600036、603823 报告中筹码段含获利比例/平均成本/集中度数值 |
| G2 | RAG 新闻在 CI 无 neodata 时仍能产出内容 | CI 产出的 4 只标的报告中，新闻 block 非空条数 ≥ 3/4 |
| G3 | 数据源不可用时可被快速定位 | CI 日志中能明确区分"接口异常""标的不适用""数据为空"三类原因 |

## 3. 现状与根因（含本次新增排查结论）

### 3.1 调用链事实（已确认）

| 模块 | 位置 | 事实 |
|---|---|---|
| 筹码调用入口 | `pipeline.py:475` | `self.fetcher_manager.get_chip_distribution(code)` |
| 多源降级 | `data_provider/base.py:2117` | 按 fetcher priority 遍历 + 熔断 |
| akshare 实现 | `data_provider/akshare_fetcher.py:1575` | `ak.stock_cyq_em(symbol=stock_code)`；已内置美股/港股/ETF 前置跳过 |
| tushare 实现 | `data_provider/tushare_fetcher.py:1151` | `cyq_chips()`，需积分（<5000 分每日 15 次） |
| 开关 | `src/config.py:1131` | `enable_chip_distribution: bool = True`（默认开） |
| 报告渲染 | `analyzer.py:3960` / `report_language.py:320` | 无 `chip` 则写"筹码分布未启用或数据源暂不可用" |
| 新闻入口 | `src/rag/retriever.py:107` → `src/rag/news.py` | neodata CLI 首选 → `search_service` 回退 → 空 block |
| neodata 路径 | `src/rag/news.py:26` | 硬编码 `C:/Users/29096/.workbuddy/.../query.py`，`_resolve_neodata_script()` 仅多一个 `Path.home()` 候选 |

### 3.2 本次新增排查结论（⚠️ 修正原假设）

> 以下为编写本 PRD 时实测所得，**改变了对根因的判断**，请架构师重点关注。

| # | 发现 | 证据 | 影响 |
|---|---|---|---|
| **F1** | **本地沙箱 Python 出网被阻断，无法作为筹码接口失效的证据** | `ak.stock_cyq_em('600036')` → `ProxyError`；剥离代理后 → `ConnectionError: RemoteDisconnected`；但同一 URL 用 `curl` 可返回 200 | 本地"筹码取不到"**大概率是环境问题而非接口失效**。不能据此判定 akshare 接口已变更。**根因定位必须以 CI 实测为准** |
| **F2** | **CI 只配置了 `DEEPSEEK_API_KEY` 一个 secret，没有 `TUSHARE_TOKEN`** | `.github/workflows/daily-analysis-v2.yml` 中 `secrets.` 仅出现 2 处，均为 DEEPSEEK | tushare 筹码兜底在 CI **当前根本不可能生效**。若要留兜底，必须新增 secret（需用户决策，见 Q3） |
| **F3** | akshare 1.18.72 已具备所需新闻接口 | `stock_news_em` / `stock_notice_report` / `stock_info_global_em` / `stock_info_cjzc_em` 均存在；`stock_zh_a_alerts_cls` 不存在 | 新增 akshare 新闻源技术可行，且 `requirements.txt` 已含 akshare，**CI 零新增依赖** |
| **F4** | news.py 结构解耦良好 | 已拆为 `_neodata_news` / `_search_service_fallback` / `_deduplicate_news` / `_format_news_block` | 新增 akshare 源只需增加一个 `_akshare_news()` 并挂入链路，**改动面小、风险低** |
| **F5** | neodata 结果解析质量粗糙 | `_parse_neodata_news()` 按行切分、取前 80 字符当标题，无结构化字段 | 多源合并后标题格式不一致，去重命中率可能下降（列入 P2） |

## 7. 待架构师决策的关键技术问题清单

> 供 P1.6 设计阶段直接承接，按决策依赖顺序排列。

### 🔴 第一优先级 — 必须先做实证，否则方案无从选型

1. **【CI 实证】筹码接口可用性验证**
   - 动作：在 GitHub Actions 上跑一次最小化验证 job，直接调用 `ak.stock_cyq_em('600036')` / `('603823')`，打印异常类型、HTTP 状态、返回行数与列名。
   - 为何必须：本地沙箱 Python 出网被阻断（`ProxyError` / `RemoteDisconnected`，而 curl 同 URL 返回 200），**本地一切失败现象都不可信**。
   - 三种结果对应三套方案：
     - **CI 可用** → 问题仅存在于本地环境，P0-1 退化为「日志增强 + 文案区分」，工作量骤减。
     - **CI 失败于反爬/请求头** → 补 UA / Referer / 重试退避即可。
     - **CI 失败于接口变更/封禁** → 需评估替换接口或启用 tushare 兜底（触发 Q3 用户决策）。

2. **【降级链设计】新闻多源策略拓扑**
   - 决策点：串行降级 vs 并行合并；akshare 源在链路中的插入位置（`search_service` 之前还是之后）。
   - 约束：CI 时间预算（analyze-emit 25min，4 标的 + max_workers=5）；本地 neodata 首选地位不变（N3）。
   - 建议默认：`neodata（本地优先）→ akshare（CI 主力）→ search_service（末位兜底）→ 空 block`，串行短路。

### 🟡 第二优先级 — 方案细节

3. **【接口选型与字段契约】** akshare 新闻接口最终取哪几个（Q4），返回 DataFrame 列名到 `{title, summary, date, source}` 的映射表，近 7 日时间窗过滤实现（Q5）。
4. **【复用边界】** 是否复用 `akshare_fetcher` 的限频/UA/熔断设施（Q7）。涉及 `src/rag/` 与 `data_provider/` 的分层约定，建议给出明确的依赖方向结论。
5. **【tushare 兜底存废】** 若 Q3 用户同意加 secret，需设计积分配额保护（每日 15 次，仅对 A 股调用、失败不重试）；若不同意，建议在代码与文档中明示「CI 无 tushare 兜底」，避免后续误判。
6. **【配置项设计】** 新增 akshare 新闻的开关/条数/超时配置，以及 P1-1 的 neodata 路径配置项，命名需对齐 `src/config.py:1250-1253` 的 `rag_*` 风格与 `parse_env_*` 解析方式（Q9）。

### 🟢 第三优先级 — 质量与可观测

7. **【诊断可观测性】** 筹码与新闻两条链路的「不适用 / 异常 / 空数据」三态日志规范，以及流程末尾的汇总行格式（P1-2）。
8. **【文案分流】** `report_language.py:320` 的提示语拆分为两条，及 `analyzer.py:3960` 的分支判断如何获知「不适用」语义（需要数据层回传原因码，而非单纯 None）—— **这是一个跨层契约变更点，需架构师明确 None 与「原因码」的接口形态**。
9. **【去重归一化】** P2-1 的跨源标题归一化规则（若本期一并做）。
