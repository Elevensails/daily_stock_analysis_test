# P1.6 数据源 CI 实证探测指南

> 配套脚本：`scripts/probe_datasource_ci.py`
> 配套 workflow：`.github/workflows/ci-probe-datasource.yml`
> 配套测试：`tests/test_probe_datasource_ci.py`（全程 mock，无网络）

## 1. 这个脚本解决什么问题

P1.6 修复了两类增量：① 筹码分布数据源（akshare `stock_cyq_em`）的失败原因码化；
② RAG 新闻检索新增 akshare `stock_news_em` 作为 CI 可用源。这两个数据源都依赖
**东方财富（东财）** 的 Web 接口，长期存在「反爬加强 / 接口字段变更」的风险。

本脚本是一个**独立 canary**：不依赖任何业务代码（data_provider / src），单独验证
「在有网环境下，东财接口是否还能正常返回」。它的价值在于：

- 一旦东财改接口 / 加强反爬，CI 日志会立刻出现异常（empty / error），
  开发者据此判断该走「调整 headers（反爬）」还是「适配新字段（接口变更）」。
- 永远不会让 CI 本身变红——失败只记录在 JSON 的 `status` 字段里。

## 2. 探测内容

| 维度 | 数据源 | 目标 |
|------|--------|------|
| `chip` | `akshare.stock_cyq_em` | 600036（招商银行）、603823（上机数控） |
| `news` | `akshare.stock_news_em` | 600036 |
| `raw_eastmoney.quote` | 裸 `requests` 直连 `push2his.eastmoney.com` kline 接口 | 验证 quote/cyq 后端通道 |
| `raw_eastmoney.news` | 裸 `requests` 直连 `np-anotice-stock.eastmoney.com` 公告接口 | 验证 news 后端通道 |

每个探测点返回四种 `status` 之一：

- `ok`：成功拿到数据
- `empty`：调用成功但返回空（可能反爬返回空页 / 无数据）
- `error`：调用抛异常（超时、连接拒绝、字段缺失等）
- `skip`：依赖库（akshare / requests）缺失，跳过

## 3. 如何运行

### 3.1 本地（需开代理 / 有网）

```bash
# 开 Clash 等代理后，确保终端能出网
python scripts/probe_datasource_ci.py --out probe-result.json
cat probe-result.json
```

常用参数：

```bash
python scripts/probe_datasource_ci.py \
  --chip-timeout 10 --news-timeout 12 --raw-timeout 10 \
  --out probe-result.json
```

### 3.2 CI（手动触发）

在 GitHub Actions 页面选择 **CI Datasource Probe (P1.6)** → `Run workflow`。
产物 `probe-result.json` + `probe-console.log` 会上传到 Artifact，并在日志末尾打印结论摘要。

> ⚠️ 本仓库本地沙箱**禁止出网**，因此该脚本**不在沙箱执行**。需用户开 Clash 后
> `git push` 触发 CI，或本地手动运行。对应测试 `tests/test_probe_datasource_ci.py`
> 全部用 mock，可在沙箱内离线跑。

## 4. 如何理解探测结果（反爬 vs 接口变更）

| 现象 | 可能原因 | 处置方向 |
|------|----------|----------|
| `raw_eastmoney` ok，但 `chip`/`news` 的 akshare 调用 `error`（字段缺失） | 东财改了返回字段（接口变更） | 更新 `data_provider` / `src/rag/_akshare_client.py` 的字段解析 |
| `raw_eastmoney` 也 `error`（连接拒绝 / 超时），且 `environment.http_proxy` 为空 | 本地未开代理 / CI 无网 | 先确认网络，再判断是否是反爬 |
| akshare 调用 `empty` 但裸请求 `ok` | akshare 的解析层被反爬（返回空页） | 参考 `data_provider/akshare_fetcher.py` 的 `_apply_chip_anti_crawl_headers` 调整 headers / User-Agent |
| `chip` 成功但 `news` 失败 | 两个接口独立，分别排查 | 新闻走 `src/rag/news.py` 的串行短路，akshare 失败会自动降级到 search_service |

## 5. 与 P1.6 代码的对应关系

- `chip` 探测对应的生产代码：`data_provider/akshare_fetcher.py::get_chip_distribution_ex`
  （失败原因码 `ChipUnavailableReason` 见 `data_provider/realtime_types.py`）。
- `news` 探测对应的生产代码：`src/rag/news.py::retrieve_news_ex` → `src/rag/_akshare_client.py::fetch_stock_news`
  （CI 首选 akshare_em，串行短路到 search_service）。
- `raw_eastmoney` 是比生产代码更底层的通道验证，用于隔离「是业务逻辑问题还是通道问题」。
